# VOD问题分类规则

## 四种问题类型

### BUG
- 判断标准: 功能已存在但行为异常/报错/结果不对/不符合预期
- 关键词: 失败、报错、异常、无法、不生效、崩溃、超时、白屏、卡死

### 功能需求
- 判断标准: 当前不存在该能力，需要新增开发
- 关键词: 不支持、缺少、希望能、建议新增、是否可以、想要、能否提供

### 体验优化
- 判断标准: 功能已有且能正常工作，但体验/性能/易用性可提升
- 关键词: 太慢、不方便、希望改进、体验差、操作复杂、建议优化、响应慢

### 其他
- 判断标准: 以上三类都不匹配
- 关键词: 咨询、疑问、文档、计费、配置、流程、政策

## 边界易混淆场景

- 功能存在但偶尔不生效 → BUG
- 功能存在但不好用 → 体验优化
- 功能存在但完全不能用 → BUG
- 希望已有功能支持更多场景 → 功能需求
- 文档描述和实际行为不一致 → BUG
- 问怎么用某个功能 → 其他
- 报了bug同时提了改进建议 → BUG（bug优先）

## 三路合并策略

分类来源有三个，按优先级合并:

1. 规则匹配(rule) — 关键词得分≥2为strong，否则weak
2. 分类匹配(category) — 结合功能分类结果+关键词
3. 知识库匹配(kb) — KB检索结果中的关键词

### 合并优先级（从高到低）

1. rule_strong: 规则强匹配
2. rule_kb_agree: 规则和KB一致
3. rule_category_agree: 规则和分类一致
4. category_strong: 分类强匹配
5. kb_strong: KB强匹配
6. rule_weak: 规则弱匹配
7. category_weak: 分类弱匹配
8. kb_weak: KB弱匹配
9. default: 其他
