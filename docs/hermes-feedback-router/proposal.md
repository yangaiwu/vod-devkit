# VOD 反馈采集意图路由（Hermes 强制评估钩子）需求文档

版本：v1.0（2026-11-06，负责人确认立项 D-hook-1）

## 一、问题

采集技能（vod-feedback-collect）的自动激活是**概率性**的。业界实测：
无钩子/简单指令钩子激活率 ~20%（与无钩子无统计差异）；强制评估注入
~84%；显式调用 100%。实锤事故：本机 hermes 会话运维上下文压过采集
意图——用户说「产品体验不好」被反问「哪个产品？要截图复现」，技能正文
根本未加载，所有文本纪律（禁问产品/原话保留）全部失效。

技能描述触发词前置（8bdc225）只解决「可见预算截断」（Hermes 索引仅前
57 字符可见，「体验差」原在截断边缘），解决不了概率路由本身。

## 二、目标

在 Hermes 宿主上落「确定性意图路由层」：每轮用户消息进入模型前，由
**代码（非模型）**做关键词判定，命中采集意图即注入激活指令（承诺机制），
把「采集 vs 排障」的分流从模型自由推理变成结构化路由。

非目标：
- 不做语义/嵌入相似度路由（M5 相似度未校准红线同口径）
- 不改变提交侧硬保障（方案 A 回显 + confirmed=false 护栏）——注入仍是
  文本指令，模型服从性天花板不变，本层提升的是命中概率（~20%→~84% 量级）

## 三、功能需求

1. 每轮用户消息进入主循环前做确定性关键词判定（pre_llm_call 钩子）
2. 命中 → 注入采集流程指令（承接+征得同意+原话逐字+一次一条+禁问产品+
   禁复现排查模式）
3. 未命中 → 零注入（不刷屏、不占上下文预算）
4. 显式前缀「提交反馈」→ 强指令（确定性短路，无需再判断意图）
5. 判定规则表单一事实源（TRIGGER_WORDS 元组，正则自动组装），新增触发词
   只改一处，有回归锁

## 四、约束

- 只覆盖 Hermes 宿主（pre_llm_call 是 Hermes 插件面）；opencode 双通路
  已实锤待实现（P2）；codex 无消息级钩子面，显式前缀兜底
- 错注入无害边界（拍板接受）：「报错/卡」在纯排障对话也会命中——指令只
  要求走采集确认流程不自动提交；漏注入才是事故
- plugins.enabled 是显式同意门，安装后需手动加名启用
