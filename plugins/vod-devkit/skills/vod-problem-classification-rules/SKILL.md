# VOD 问题分类规则（引擎 v2 口径）

> 真源纪律：本技能内容以引擎代码为准（n01_classify.py DEFAULT_TYPE_DEFS
> + 分类 prompt），2026-11-03 逐行核对。旧四类口径（BUG/功能需求/
> 体验优化/其他）已废弃，与引擎不符——它来自过期文档。
> 采集定位：预分类仅作参考 hint（tags），引擎 LLM 按六类重判——
> 预分类不是终局，别和用户言之凿凿。

## 六类定义（引擎 DEFAULT_TYPE_DEFS 原文）

| 类型 | 判定 |
|---|---|
| 产品缺陷 | Bug / 功能不可用 / 报错崩溃 |
| 技术/业务咨询 | 询问用法 / 支持能力 |
| 体验改进 | 可用但体验差，求优化交互/性能/UI |
| 主观评价 | 纯感受 / 评分 / 对比，无具体诉求 |
| 无效问题 | 内容不完整 / 无意义 / 重复 / 非产品（唯一跳过后续分析的类型） |
| 功能需求 | 要求新增功能 / 能力 |

## 判定细则（引擎分类 prompt 摘要）

- NPS 打分开头 → 主观评价
- 竞品对比但无具体差异 → 主观评价
- 纯情绪无场景 → 主观评价
- 定价/价格类诉求：有具体功能建议 → 功能需求/体验改进；无 → 主观评价
- 纯好评无建议 → 主观评价
- 「希望 XX」按实际归类：功能/能力 → 功能需求；交互/UI/性能 → 体验改进

## 引擎分类流程（v2.2）

全量走 LLM 六段式分类（规则预判已移除），fewshot 示例动态检索；
少数派结果自动重试。旧 problem_classifier.py 的两类口径
（问题反馈/产品咨询）为遗留代码，不在 v2 主链。

## 采集用法

agent 采集时按上表打 tags（如 problem_type=体验改进），仅作预分类
参考；不确定就不填，别硬猜——引擎 LLM 会重判，错误预分类比留空
更糟（可能干扰 fewshot 检索）。
